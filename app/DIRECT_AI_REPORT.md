## Implementation

Set `AI_LIVE_MODE=direct` with the existing `AI_BASE_URL`, `AI_API_KEY` and exact `AI_MODEL`. Direct mode bypasses session authentication and application minute/day/concurrency caps. It does not read Redis, require a passcode/signing secret or use an origin allowlist. Existing guard variables can stay configured; direct mode ignores them. Provider and platform limits still apply. Anyone visiting the demo can request provider work billed to the configured account.

The key remains server-only. Same-origin browser mutations are checked, hosted requests require HTTPS, provider requests retain timeout/no automatic retries/redirects, and all existing scope/schema/citation/number validation and replay behavior remain. Origin checks do not restrict visitors or prevent a caller from reproducing the website's request. Direct mode is intentionally public. Missing key/model disables its gateway; normal-only observations still do not request diagnosis. Default mode stays disabled; local and protected public modes retain their existing guards.

The existing gateway shows availability text and enables the existing composition button, with no passcode or lock controls. It does not show successful integration until a request has a validated response. No CSS, theme, assets, source originals, normalized data, financial formulas, temporal eligibility, action/drawer scope or closure workflow was modified.

Changed runtime files: `src/lib/live-access.ts`, `src/lib/analysis-service.ts`, `src/app/api/demo-session/route.ts`, `src/components/demo-access.tsx`. Added regression coverage in `tests/repair.test.ts`, `tests/direct-browser.spec.ts`, `playwright.direct.config.ts`, and `scripts/verify-direct-browser.ts`. Package scripts, gitignore, env example, root/app README, DESIGN, UX-CONTRACT and status/report document the explicit mode. Dependencies and lockfile are unchanged.
